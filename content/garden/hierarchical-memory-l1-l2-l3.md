# 階層化メモリ構造：L1・L2・L3ステート管理の定義

AIと長編を書くとき、情報を全部同じ場所に置くと破綻する。人間の記憶に倣って3層に分けると、渡す情報と保存する情報を切り分けられる。

## L1：作業記憶（コンテキスト内）

- 直前のシーンの本文
- 今のシーンの目的
- 登場人物の口調の見本（3行）
- 直前話の要約（300字）

揮発する。生成が終われば消える。ここに入れるのは「今書くために必要なもの」だけ。

## L2：作品記憶（作品フォルダ）

- 世界観、技術仕様、人物、舞台
- 伏線台帳、時系列、用語集
- 各話の本文と章の要約

作品が終わるまで残る。LLMには必要に応じて一部だけ渡す。Obsidianのアトミックノートがこれにあたる。

## L3：長期記憶（Vault全体）

- 過去の作品、読書メモ、日々の思索
- 文体の好み、失敗の記録
- 他のプロジェクトで得た知見

作品を越えて残る。ここからL2へ持ち上げて使う。今回のガーデンやnote記事も、L3に属する。

## 昇格と降格

- **昇格**：L3の断片が今の作品に効くと分かったら、L2にコピーして具体化する（抽象的な論を、作品の設定に翻訳する）。
- **降格**：L2の詳細がもう使わないなら、要約だけ残してL3へ移す。終わった作品の設定を毎回渡さない。

## 運用のコツ

LLMに渡すときは、L1→L2→L3の順に予算を割り当てる。L3を大量に渡すと、L1が薄くなる。コンテキストの枯渇は、ほぼこの配分ミスで起きる。

## どこまで実装したか

第1話の時点で動いていたのは、L1（シーンごとのプロンプト）とL2（設定8ノート）まで。L3はまだ配線していない。過去作や読書メモを作品に引き上げる仕組みは、作品が2つ目になったときに入れる。この節は、実装が進むたびに更新する。
