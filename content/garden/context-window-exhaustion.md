# AI小説執筆におけるコンテキストウィンドウの枯渇問題

長編をAIと書いていて、最初にぶつかる壁がこれだ。コンテキストウィンドウには上限がある。上限に近づくと、AIは前半の情報を落とす。落とし方が急で、しかも本人（AI）は落としたことに気づかない。

## 枯渇すると起きること

- **声が変わる**：一人称や口調が、序盤と終盤で別人物になる。
- **設定を再発明する**：NCIの機能が、書くたびに少しずつ変わる。
- **同じ説明を繰り返す**：読者は既に知っている設定を、毎話説明される。
- **伏線を忘れる**：植えたことを忘れ、回収しない。あるいは別の形で回収する。

## なぜ「全部渡す」が失敗するのか

全部渡せば忘れない、と思う。逆だった。全部渡すと、AIは**今書くシーンと後半の伏線を区別できない**。結果として、まだ明かすべきでない情報を冒頭で親切に説明する。情報量が増えるほど、推論の焦点がぼける。

これはコンテキストの量の問題ではなく、**注意の配分**の問題だ。

## 回避策

1. **シーン単位で書く**：1回の生成を1,200〜1,600字に固定する。
2. **渡すノートを選ぶ**：そのシーンに出る人物と舞台だけ。
3. **要約を階層化する**：直前話の要約（300字）、章の要約（300字）、全体の要約（300字）。必要に応じて使い分ける。
4. **状態は外に置く**：伏線、時系列、人物の口調はファイルに逃がす。

## コストの話

コンテキストを節約することは、トークン代の節約にもなる。無料枠のモデルを使う場合、ここは品質と財布の両方に効く。[[autonomous-ai-agents-token-consumption-free-tier|エージェントのトークン消費]]とも関係する。
