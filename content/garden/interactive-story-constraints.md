# インタラクティブなストーリー展開における制約条件の設計

読者が物語の展開を選べる形にすると、どこかで破綻する。分岐が増えるほど、書く量と整合性のコストが指数的に増えるからだ。このノートは、その制約をどう設計するかのメモ。まだ実装していない構想。

## 選択の階層

- **態度の選択**：登場人物にどう接するか。物語の骨格は変わらない。
- **順序の選択**：どのエピソードを先に読むか。真相は変わらない。
- **結末の選択**：エンディングが分岐する。ここを許すと、書く量が跳ね上がる。

最初に許すなら、態度の選択だけがいい。読者は参加している感覚を得られるが、作者は一つの筋を書けばいい。態度の違いは、同じシーンの台詞と地の文を差し替えるだけで表現できる。

## 状態の持ち方

選択の結果は、読者ごとの状態として保持する必要がある。

```json
{
  "reader_id": "...",
  "flags": {
    "trust_iori": 2,
    "told_about_nci": true
  }
}
```

このフラグを、次のシーンのプロンプトに渡す。渡すのは**今のシーンに効くフラグだけ**。全部渡すと、AIが過去の選択を親切に説明し始める。

## 制約の設計原則

1. 選択は、後のシーンで必ず一度は触れる（無視された選択は信用を失う）。
2. 選択によって、消えるルートを作らない（読者は損をしたと感じる）。
3. 分岐は、人物の関係値だけに閉じる（世界のルールは変えない）。

3番目が一番大事で、世界のルールを可変にすると、[[can-ai-novel-stay-coherent|破綻しない小説]]を作るのが難しくなる。インタラクティブにできるのは、物語の表面だけだと思う。
