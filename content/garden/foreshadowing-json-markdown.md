# 長編小説における伏線とフラグのJSON-Markdown管理

伏線は、植えた瞬間に忘れられる。人間でも忘れるのだから、AIはもっと忘れる。忘れないようにするには、**植えたことを記録する場所**を決めるしかない。

## そもそもJSONとは何か

エンジニアでなくても読めるように書くと、JSONは「**項目名と値のペアを並べたメモ**」だ。表計算ソフトの1行を、縦に書き下しただけに近い。

| id | planted | payoff | status | summary |
| :--- | :--- | :--- | :--- | :--- |
| F001 | ep01 | ep04 | open | 旧校舎の雨音。透の記憶とNCIのログが食い違う |

この1行が、こうなる。

```json
{ "id": "F001", "planted": "ep01", "payoff": "ep04", "status": "open", "summary": "旧校舎の雨音。透の記憶とNCIのログが食い違う" }
```

つまり、**表を機械が読める形にしたもの**。見た目が記号だらけなだけで、やっていることは台帳づくりと変わらない。むしろ、この形にしておくと「`status` が `open` の行だけ」を機械的に選べるのが強い。

## なぜ表計算ソフトではだめなのか

表でもいいのだが、AIに渡すときに弱点が出る。ExcelやCSVは、どの列が何を意味するかを毎回説明しなければならないし、Markdownの文章に混ぜると表が崩れやすい。

JSONなら、キーの名前がそのまま意味になる。`status` は状態、`payoff` は回収予定の話数。AIはこれを読むだけで構造を理解できる。**人間が表として読めること**と、**AIが構造として読めること**の両立が、JSONを選んだ理由だ。

## JSONは自分で書かなくていい

ここが一番大事かもしれない。手で書くと括弧を間違える。

- AIに「この伏線をJSONに追記して」と頼む
- 自分は書き上がったものを表として確認する
- 状態を変えるときも、AIに「F001を `paid` にして」と伝える

つまり、**JSONは人間が書くためではなく、人間とAIが同じ台帳を見るための形式**だ。読めなくても、表として読めれば運用できる。

## なぜJSONとMarkdownの併用か

- **JSON**：状態を機械的に判定できる。LLMに「未回収だけ渡す」ができる。
- **Markdown**：意味とニュアンスを人間が読める。なぜその伏線を植えたかは、JSONに書くと窮屈。

だから、状態はJSON、意味はMarkdownの本文に置く。

## スキーマの例

```json
{
  "foreshadowing": [
    {
      "id": "F001",
      "planted": "ep01",
      "payoff": "ep04",
      "status": "open",
      "summary": "旧校舎の雨音。透の記憶とNCIのログが食い違う",
      "note": "回収時は、答えを説明せず、別の違和感に置き換える"
    }
  ]
}
```

`status` は `open` / `paid` / `abandoned` の3つで足りる。`abandoned` を許すのが大事で、全部回収しようとすると話が窮屈になる。

## 運用

1. シーンを書いたら、植えた伏線をJSONに追記する。
2. 回収したら `status` を `paid` にする。**消さない**。消すと、後から経緯を追えなくなる。
3. 次のシーンを書くとき、LLMには `open` のものだけ渡す。`paid` を渡すと、AIが「これはもう回収済みです」と親切に説明し始める。

## 運用状況

これは設計であって、まだ実績ではない。第1話では、伏線を本文と全体プロットのノートで追っていた。台帳を用意したのは、連載が続くと破綻すると分かってからだ。第2話から使う。

使ってみて分かったこと（`paid` を渡したら何が起きたか、`abandoned` を実際に使ったか）は、この節に追記していく。

## フラグとの違い

伏線は読者に対する約束、フラグは物語内部の状態（誰が何を知っているか）。混ぜると管理できないので、別のキーに分ける。

ゲームで「このイベントを見たか」「この鍵を持っているか」を記録するあれが、フラグだ。小説でも同じで、「透はNCIの真実をもう知っているか」「水野の信頼度はいくつか」を、文章とは別に持っておく。これを文章だけで管理すると、AIは前の話を忘れる。

```json
{
  "flags": {
    "iori_knows_about_nci": true,
    "mizuno_trust": 2
  }
}
```
